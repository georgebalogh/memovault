01 A gyökérprobléma

Ha egy osztály maga példányosítja a függőségét, három fájdalmat okoz:

  • Tesztelhetetlen — nem tudod lecserélni fake-re
  • Merev csatolás — a változás dominóeffektusa végigmegy a kódon
  • Nem cserélhető futás közben — be van égetve az implementáció
❌ ROSSZ
public class OrderService
{
    private readonly EmailSender _emailSender;

    public OrderService()
    {
        _emailSender = new EmailSender(); // maga példányosítja
    }
}
Az osztály nem csak használja a függőségét — hanem felelős annak létrehozásáért is. Ez a két dolog össze van mosva.
✅ JÓ
public class OrderService
{
    private readonly IEmailSender _emailSender;

    public OrderService(IEmailSender emailSender) // kívülről jön
    {
        _emailSender = emailSender;
    }
}
new belülDI-val kívülről

02 A mögöttes elvek — SRP → DIP → IoC → DI
SRP felismeri: "Ez az osztály túl sokat tud / csinál" ↓ DIP kimondja: "Függj absztrakciótól, ne konkrétumtól" ↓ IoC megfordítja: "Ne te hozd létre — add át a vezérlést" ↓ DI megvalósítja: "A függőséget kívülről injektáljuk be"
DIP — a kulcsgondolat

Magas szintű modulok ne függjenek alacsony szintűektől. Mindkettő absztrakciótól függjön.

03 Mikor éri meg
Van mellékhatása a függőségnek? (IO, hálózat, DB) ├── Igen → DI szinte biztosan indokolt └── Nem → Kell-e tesztelni izoláltan? ├── Igen → DI érdemes └── Nem → Lesz-e több implementáció? ├── Igen → DI érdemes └── Nem → Valószínűleg felesleges
KontextusDI érdemes?
Mellékhatásos függőség (DB, API, e-mail)✅ igen
Unit tesztek kellenek✅ igen
Több implementáció várható✅ igen
Nagy csapat, hosszú projekt✅ igen
Pure logic, value object❌ nem
Prototípus, kis projekt❌ általában nem
Stabil, soha nem változó segédosztály❌ nem
A DI komplexitást ad cserébe rugalmasságért és tesztelhetőségért. Ez csak akkor éri meg, ha ténylegesen élsz ezekkel az előnyökkel.

✅ V2 — interfészek + konstruktor injektálás
public class OrderProcessor
{
    private readonly IInventoryService       _inventory;
    private readonly IPaymentGateway         _payment;
    private readonly INotificationService    _notifier;
    private readonly ILogger<OrderProcessor> _logger;

    public OrderProcessor(
        IInventoryService inventory,
        IPaymentGateway payment,
        INotificationService notifier,
        ILogger<OrderProcessor> logger)
    {
        _inventory = inventory;
        _payment   = payment;
        _notifier  = notifier;
        _logger    = logger;
    }

    public void Process(Order order)
    {
        if (!_inventory.CheckStock(order.ProductId, order.Quantity))
        {
            _logger.LogWarning("Nincs készlet: {ProductId}", order.ProductId);
            return;
        }
        if (!_payment.Charge(order.CustomerId, order.TotalAmount))
        {
            _logger.LogWarning("Fizetés sikertelen: {CustomerId}", order.CustomerId);
            return;
        }
        _inventory.ReduceStock(order.ProductId, order.Quantity);
        _notifier.Notify(order.CustomerEmail, "Rendelés visszaigazolva");
        _logger.LogInformation("Rendelés feldolgozva: {OrderId}", order.Id);
    }
}

builder.Services.AddScoped<IInventoryService>(_ =>
    new SqlInventoryService(connectionString));

    new StripePaymentGateway(stripeApiKey));
